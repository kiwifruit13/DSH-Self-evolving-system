| 主代理不持有写操作组件 | 🔴 **严重偏离** | `self._compiler = SkillCompiler(storage)` — SkillCompiler 包含 `upsert_skill` 写方法 |

**🔴 严重偏离 2.1**：MainAgent 持有 `SkillCompiler` 实例

**证据**：`src/main_agent.py` 第 99 行

```python
def __init__(self, storage: Storage, pending_queue: PendingQueue):
    ...
    self._compiler = SkillCompiler(storage)  # ← 持有写操作组件
```

虽然 MainAgent 实际只调用了 `SkillCompiler` 的读取方法（`get_skill_for_entry`、`get_skill`），但持有写能力组件违反了 CQRS 的**防御性编程原则**——组件的能力边界应该在其暴露的接口上，而不应依赖调用方的"自我克制"。

**建议**：提取一个只读的 `SkillRepository` 接口（或直接从 Storage 读取 Skill），将 `SkillCompiler` 从 MainAgent 的依赖中移除。

### 2.3 子代理关键缺陷

**🔴 严重缺陷 2.3**：SubAgent 新建路由表节点未持久化到数据库

**证据**：`src/sub_agent.py` 第 279-329 行

```python
def _process_feedback(self, pkg) -> RoutingTableEntry | None:
    existing = self._storage.get_routing_entry(category_id)
    if existing is not None:
        # 已有节点路径：正确更新并持久化 ✅
        existing.stats["freq"] = existing.stats.get("freq", 0) + 1
        existing.local_map.append_log(...)
        self._storage.upsert_routing_entry(existing)  # ← 有持久化
        return existing

    # 新节点路径：构建对象但 NEVER 持久化 ❌
    lm = LocalMindMap(...)
    ...
    return RoutingTableEntry(...)  # ← 只返回对象，不写数据库！
```

`consume_pending()` 第 267-272 行调用后使用返回的 entry 编译 Skill，但 routing table 表中的该条目**从未被写入**。

**后果**：
1. 子代理消费暂存队列后，路由表中**不会增加任何新节点**
2. 后续主代理查询时永远找不到这些节点
3. Skill 编译器仍能从内存对象编译 Skill 并写入 skills 表，造成 skills 与 routing table 脱节
4. 框架的核心闭环（未知反馈 → 路由表新增 → Skill 孵化）在"路由表新增"这一步断裂

**根因**：`_process_feedback()` 对"已有节点"路径有 `upsert`，但"新节点"路径缺失了对称的 `upsert` 调用。

**建议**：在 `_process_feedback()` 返回前添加 `self._storage.upsert_routing_entry(entry)`。

## 五、四维排序计算器审计

**约束公式**（AGENTS_01.md §2.2）：
```
综合优先级 = Freq × 0.25 + Impact × 0.35 + Trend × 0.20 + Recover_Cost × 0.20
衰减因子 = 2^(-days_since_last_seen / 7)
最终得分 = 综合优先级 × 衰减因子
```

### 5.1 公式正确性

| 维度 | 约束权重 | 代码权重 | 结果 |
|------|---------|---------|------|
| Freq | 25% | `freq_weight = 0.25` | ✅ |
| Impact | 35% | `impact_weight = 0.35` | ✅ |
| Trend | 20% | `trend_weight = 0.20` | ✅ |
| Recover_Cost | 20% | `cost_weight = 0.20` | ✅ |
| 时间衰减 | 半衰期 7 天 | `half_life_days = 7.0` | ✅ |
| 衰减公式 | `2^(-days/7)` | `2.0 ** (-days / half_life_days)` | ✅ |

### 5.2 归一化函数

| 函数 | 约束 | 代码实现 | 结果 |
|------|------|---------|------|
| `normalize_freq` | 0→0.0, max→1.0, >max→1.0 | 线性钳制 | ✅ |
| `normalize_impact` | [0,1] 钳制 | `max(0.0, min(1.0, impact))` | ✅ |
| `normalize_trend` | [-1,1]→[0,1] | `(trend + 1.0) / 2.0` 再钳制 | ✅ |
| `normalize_cost` | 0→1.0, max→0.5, ∞→0.0 | 反向 sigmoid `1/(1+ratio)` | ✅ |

### 5.3 数据源审计

| 维度 | 数据源 | 状态 | 结果 |
|------|--------|------|------|
| Freq | `stats["freq"]` — 蒸馏/反馈时更新 | ✅ 有数据 |
| Impact | `stats["impact"]` — 从置信度推断 | ✅ 有数据 |
| Trend | `stats["trend"]` — **永远硬编码为 0.0** | 🟡 **无效维度** |
| Recover_Cost | `stats["recover_cost"]` — 从尝试策略数推算 | ✅ 有数据 |

- 与 `待完善/设计待完善.md` P0-1 一致
