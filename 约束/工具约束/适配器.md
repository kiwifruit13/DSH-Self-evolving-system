下面是对 **添加工具与适配器** 这一主题的完整展开。

---

## 一、总体模型

DeepSeek Harness 中，模型所见的一切能力——文件 I/O、Shell 执行、Web 检索——都是一个**已注册的工具**；每一个模型提供商都是一个**已注册的 LLM 适配器**。二者遵循**相同的 Cordis 插件契约**：

1. 声明一个 `name`
2. 通过 `inject` 注入注册表服务
3. 在 `apply()` 中完成注册

销毁插件纤程会**自动注销**其贡献，构造上即满足 HMR 安全与生命周期正确。

## 二、工具注册：最小形态

```ts
export const name = 'my-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'read_file',
    description: 'Read a file from disk.',
    parameters: {
      path: { type: 'string', required: true },
      limit: { type: 'number' },
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args, exec) {
      // 工具主体逻辑
    },
  }))
}
```

**`defineTool` 做了什么：**
- 将 `parameters` 编译为原始 JSON Schema
- 在 `execute` 运行前**自动校验**模型生成的参数（类型、必填键、字面量约束、精确单一联合、嵌套值），违规抛出 `ToolArgsError`
- 在类型层级推导出精确的 `args.path: string` / `args.limit?: number`——无需手动类型转换

注册是基于效应的：插件纤程销毁 → 工具注销 → 模式从下一次系统提示词组装中移除。

来源：[adding-a-tool.md](docs/cookbook/adding-a-tool.md#L53-L58)

## 三、`execute()` 契约（7 条硬规则）

| # | 规则 | 说明 |
|---|------|------|
| 1 | **参数已校验** | `defineTool` 在 `execute` 前拒绝违反模式的参数 |
| 2 | **注册借只读引用** | 注册后不可修改模式或替换回调；热替换需销毁效应后重新注册 |
| 3 | **执行身份受保护** | 管线在守卫边界冻结执行状态，后续策略无法篡改 |
| 4 | **返回值必须通过 output.schema** | 规范值契约：`execute()` 返回值必须通过 `output.schema` 验证 |
| 5 | **领域成功 ≠ 基础设施成功** | 基础设施故障抛异常；即使文本是错误消息，规范值中也应表示领域结果 |
| 6 | **遵从 `exec.signal`** | `AbortSignal` 触发时取消进行中工作——**强制性**，注册表通过环绕调度信号替换保留调用者的取消 |
| 7 | **使用 `presentationMeta` 投影持久卡片数据** | 可选，但变更类工具（write/edit）需要它：核心将投影 JSON 持久化在 `tool/result` 上并传给 `presentResult` |

来源：[schema.ts](packages/core/tools/src/schema.ts#L480-L570), [index.ts](packages/core/tools/src/index.ts#L200-L260)

## 四、表现层：`presentCall` 与 `presentResult`

工具通过两个纯函数向 UI 投影渲染意图：

| 函数 | 阶段 | 约束 | 用途 |
|------|------|------|------|
| `presentCall?(args)` | 调度时 | 纯、无副作用、重放安全 | 生成**待定状态卡片**（pending card） |
| `presentResult?(args, result)` | 结果发射时 | 纯、无副作用、重放安全 | 生成**完成状态卡片**（completed card） |

### 待定状态卡片种类

| 卡片种类 | 使用时机 |
|-----------|----------|
| `generic` | 通用操作：显示 title、kind、rawInput、content |
| `command` | Shell/子进程命令 |
| `code-edit` | 代码编辑预览 |
| … | 其他领域特定卡片 |

**关键约束：**
- `presentCall` 必须仅依赖 `args`——同一函数在实时流传输和会话日志重放期间运行
- 工具包（`dsh-tools`）**绝不导入** UI 或传输类型——中性词汇；宿主/客户端运行时将每个 `card` 映射为自身的视图组件
- `defineTool` 软校验显示路径：畸形的已记录参数返回 `undefined`（通用回退）而非抛异常——显示**绝不能**导致重放崩溃

来源：[presentation.ts](packages/core/tools/src/presentation.ts)

## 五、执行策略与观察钩子

**核心原则：不要将部署策略构建到工具本身中。** 工具只声明它做什么；策略（超时、重试、指标、沙箱审批）挂载到管线事件上：

| 事件 | 模式 | 用途 |
|------|------|------|
| `tools/pre-execute` | 瀑布流 | 允许、拒绝或调度前询问 |
| `tools/execute` | 瀑布流（环绕调度） | 超时、重试或指标包装器 |
| `tools/post-execute` | 瀑布流 | 接受、替换、丰富或阻塞规范化结果 |
| `tools/code-dispatch-log` | 瀑布流 | 替换 `run_code` 子调度持久日志副本中的内容 |
| `tools/result` | 发射 | 最终结果提交 |

## 六、LLM 适配器注册：最小形态

```ts
export const name = 'my-adapter'
export const inject = ['llm']

export function apply(ctx: Context) {
  ctx.llm.registerAdapter(['provider-route'], MyAdapter)
}
```

- 每个提供商路由对应一个适配器——重复项抛异常
- 多路由注册为**全有或全无**
- `options.provider` 选择适配器，`options.model` 为提供商模型 ID——动态目录适配器无需生命周期重配置即可提供新模型

来源：[adding-an-llm-adapter.md](docs/cookbook/adding-an-llm-adapter.md#L1-L44)

## 七、适配器协议契约

`stream()` 生成器必须满足精确协议（已在 `llm-deepseek` 和 `llm-pi-ai` 两个生产级实现上校验）：

| 规则 | 详情 |
|------|------|
| **归因标头强制** | 每个 HTTP 请求必须包含 `attributionHeaders()`，注册中心在传输层强制执行 |
| **配置快照语义** | 进行中的请求绝不会看到操作中途的配置变更——`prepareCall()` 在 harness 层强制执行，适配器内部也必须针对自身连接事实强制执行 |
| **瀑布流异常传播** | 监听器失败保持抛出状态——作为插件错误传播给消费者 |
| **适配器边界失败转换** | 注册中心在 `adapterStream()` 内部将适配器边界失败转换为终止的 `error` 或 `aborted` 完成块 |

来源：[adding-an-llm-adapter.md](docs/cookbook/adding-an-llm-adapter.md#L20-L44)

## 八、适配器实现结构

将各层保持为**独立职责**：

```
packages/llm/llm-my-provider/
├── adapter.ts        # 适配器类：stream()、配置、生命周期
├── serialize.ts      # GenerateOptions → 提供商请求体
├── parse.ts          # SSE 行 → 提供商块
├── translate.ts      # 提供商块 → StreamChunk 翻译  ← 先实现这个！
├── types.ts          # 提供商特定的线路类型
├── invariant.ts      # 协议断言辅助函数
└── index.ts          # 插件入口：apply()、Config、注册
```

> 💡 **先实现 `translate.ts`**——块到 StreamChunk 的映射是大多数提供商怪异之处显露的地方。

来源：[adapter.ts](packages/llm/llm-deepseek/src/adapter.ts)
