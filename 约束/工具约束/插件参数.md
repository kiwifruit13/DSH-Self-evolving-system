# Cordis 插件定义参数完整拆解

Cordis 中"定义插件"的核心 API 是 `ctx.plugin()`，它接受三种形态的插件对象，每种都共享一组元数据字段。以下逐层展开。

---

## 一、插件三种形态

来自 [registry.ts#L91-L133](vendor/cordis/src/registry.ts#L91-L133)：

```ts
type Plugin<T = any> =
  | Plugin.Function<T>    // 函数插件
  | Plugin.Constructor<T> // 类插件（服务）
  | Plugin.Object<T>      // 对象插件
```

| 形态 | 签名 | 适用场景 | 示例 |
|------|------|----------|------|
| **函数** | `(ctx: Context, config: T) => any` | 大多数插件：简单注册副作用 | `export function apply(ctx, config) {}` |
| **类** | `new (ctx: Context, config: T) => any` | 需要在 `ctx` 上暴露命名能力（服务提供者） | `export class MyService { constructor(ctx, config) {} }` |
| **对象** | `{ apply(ctx: Context, config: T): any }` | 需要与 `apply` 并存的命名元数据 | `export const plugin = { name: 'x', apply(ctx) {} }` |

`ctx.plugin()` 会自动识别形态——函数直接调用，类执行 `new`，对象调用 `.apply()`。

---

## 二、共享元数据：`Plugin.Base`

每种形态都继承自 `Plugin.Base<T>`（[registry.ts#L100-L111](vendor/cordis/src/registry.ts#L100-L111)），这是插件定义的**参数全表**：

```ts
interface Base<T = any> {
  name?: string                          // 显示名
  Config?: StandardSchemaV1<any, T>      // 配置 schema
  inject?: Inject                        // 依赖声明
  provide?: string | string[]            // 提供的服务名
  intercept?: Dict<boolean>              // 声明消费的拦截配置
}
```

逐字段详解：

### 1. `name` — 显示名

- 类型：`string`（可选）
- 用途：纤程诊断日志名、logger 名称
- 默认：未声明时由 Cordis 从文件路径/类名推导

```ts
export const name = 'my-greeter'
```

### 2. `Config` — 配置 Schema

- 类型：`StandardSchemaV1<any, T>`（可选）
- 作用：**双重身份**——既是 TypeScript 接口，也是运行时校验器
- 时机：纤程从 `PENDING → LOADING` 之前校验；失败则进入 `FAILED` 状态，`apply` 永不执行
- 本仓库使用 [Schemastery](https://github.com/shigma/schemastery) 作为 Standard Schema 实现

```ts
import Schema from '@deepseek-ai/schemastery'

export interface Config {
  greeting: string
  targets: string[]
  port: number
}

export const Config = Schema.object({
  greeting: Schema.string().default('Hello'),
  targets: Schema.array(Schema.string()).default([]),
  port: Schema.number().required(),
})
```

`cordis.yml` 中对应：

```yaml
- name: './my-plugin.ts'
  config:
    greeting: 'Hi'
    targets: ['alpha', 'beta']
    port: 8080
```

**`apply` 接收的 `config` 已校验且含默认值**——不需要手动检查 `undefined` 或回填默认值。

### 3. `inject` — 依赖声明

- 类型：`Inject`，即 `(keyof M)[] | { [K in keyof M]?: M[K] }`
- 作用：声明此插件依赖哪些服务；所有声明的服务可用后才从 `PENDING → LOADING`
- 两种形式：

```ts
// 数组形式：仅声明依赖，不带拦截配置
export const inject = ['greeter', 'logger']

// 对象形式：声明依赖 + 附带拦截配置
export const inject = { greeter: { prefix: '>>' }, logger: null }
```

`Inject.resolve()` 将两种形式归一化为 `{ 服务名 → 拦截配置 | null }` 的扁平映射（[registry.ts#L71-L88](vendor/cordis/src/registry.ts#L71-L88)）。

**加载顺序由依赖图决定，不依赖 `cordis.yml` 中的声明顺序。**

### 4. `provide` — 提供的服务名

- 类型：`string | string[]`（可选）
- 作用：声明此插件向 `ctx` 上暴露的服务名称；供其他插件的 `inject` 引用
- 类插件自动将类名注册为服务；此字段用于显式覆盖或声明额外服务

```ts
// 函数插件显式提供服务
export const provide = 'my-greeter'
export function apply(ctx: Context) {
  ctx.provide('my-greeter', { greet: (name) => `Hello, ${name}!` })
}

// 类插件：provide 可覆盖默认类名
export class MyGreeter {
  static provide = ['greeter', 'welcomer']
  constructor(ctx: Context) { /* ... */ }
}
```

### 5. `intercept` — 声明消费的拦截配置

- 类型：`Dict<boolean>`（可选）
- 作用：声明此插件会**读取**哪些服务的拦截配置键；工具链用于依赖分析，不影响运行时行为
- 拦截配置本身通过 `ctx.intercept(name, config)` 在上下文层注入

```ts
export const intercept = { llm: true }  // 声明消费 llm 的拦截配置
```

## 三、`ctx.plugin()` 调用签名

来自 [registry.ts#L185](vendor/cordis/src/registry.ts#L185)：

```ts
ctx.plugin<P extends Plugin>(
  plugin: P,
  ...args: Spread<GetPluginConfig<P>>
): Fiber & PromiseLike<Fiber>
```

- `plugin`：函数/类/对象插件
- `args`：可选的配置对象，会被校验后传入 `apply(ctx, config)`
- 返回：纤程（thenable，`await` 等待加载完成）

`Spread<T>` 的逻辑：如果 `T` 包含 `undefined`（即 Config 可选），则 `config` 参数可选；否则必填。

---

## 四、`ctx.inject()` 简写

```ts
ctx.inject(deps: Inject, callback: Plugin.Function<void>): Fiber & PromiseLike<Fiber>
```

等效于 `ctx.plugin({ inject: deps, apply: callback })`。适合短生命周期/响应式逻辑——依赖变更时自动重新运行回调，天然支持热重载。

## 五、完整插件定义示例

### 函数插件（最常见形态）

```ts
import type { Context } from '@deepseek-ai/cordis'
import Schema from '@deepseek-ai/schemastery'

export const name = 'greet-tool'
export const inject = ['tools']           // 依赖 tools 服务

export interface Config {
  greeting: string
  targets: string[]
}

export const Config = Schema.object({
  greeting: Schema.string().default('Hello'),
  targets: Schema.array(Schema.string()),
})

export function apply(ctx: Context, config: Config) {
  // config.greeting: string（已校验，已填默认值）
  // config.targets: string[]（已校验）
  ctx.tools.register(defineTool({ /* ... */ }))
}
```

### 类插件（服务提供者）

```ts
import { Service } from '@deepseek-ai/cordis'

export class Greeter extends Service {
  static inject = ['logger']

  constructor(ctx: Context, config: {}) {
    super(ctx, 'greeter', true)   // 服务名 'greeter', 立即可用
  }

  greet(name: string) {
    return `Hello, ${name}!`
  }
}
```

### 对象插件

```ts
export const plugin = {
  name: 'my-object-plugin',
  inject: ['tools'],
  Config: Schema.object({ /* ... */ }),
  apply(ctx: Context, config: any) {
    // ...
  },
}
```

## 六、纤程状态机与参数校验时机

```
PENDING ──(Config 校验)──→ LOADING ──(apply 完成)──→ ACTIVE
   │                         │
   │  inject 依赖缺失         │  apply 抛异常
   ↓                         ↓
  停留 PENDING              FAILED
```

| 校验点 | 校验内容 | 失败后果 |
|--------|---------|---------|
| PENDING → LOADING | `Config` schema 校验原始配置 | `FAILED`，`apply` 不执行 |
| PENDING → LOADING | `inject` 声明的服务是否全部可用 | 停留 `PENDING`，等待依赖 |
| LOADING → ACTIVE | `apply()` 正常返回 | `ACTIVE` |
| LOADING → FAILED | `apply()` 抛异常 | `FAILED` |

## 七、`Plugin.Transform` — 配置变换

[registry.ts#L113-L118](vendor/cordis/src/registry.ts#L113-L118) 定义了一个特殊形态：

```ts
interface Transform<S, T> {
  schema?: true           // 标记为变换对象
  Config: (config: S) => T // 用户配置 → 运行时配置
}
```

用于将用户友好的配置形态 `S` 转换为内部运行时形态 `T`。`ctx.plugin()` 会先识别 Transform，对配置做变换后再传给实际插件。
