`cordis_define`（实际导出名为 `defineTool`）的工具参数 schema 校验机制涉及**两层防线**：编译时 schema 编译 + 运行时参数校验。以下是校验流程与常见问题拆解：

---

### 校验流程

1. **Schema 编译阶段**（`defineTool` 调用时）：作者的 `parameters` 被编译为原始 JSON Schema，同时执行**子集校验**——只允许以下关键字：

   | 类别 | 允许的关键字 |
   |------|-------------|
   | 约束 | `type`, `oneOf`, `properties`, `required`, `additionalProperties`, `items`, `enum`, `const` |
   | 注解 | `description`, `title`, `default`, `examples` |

   不在此列表中的关键字（如 `pattern`, `format`, `minLength`, `maxLength`, `minItems`, `maxItems`, `$ref`, `anyOf`, `allOf` 等）会被 **`JsonSchemaError`** 拒绝，报错形如 `schema.xxx is not a supported keyword`。

   参见 [json-schema.ts](packages/core/tools/src/json-schema.ts#L76-L87) 中的关键字白名单，以及 [schema.ts](packages/core/tools/src/schema.ts#L193-L197) 中的 `assertAuthorKeys` 校验。

2. **运行时参数校验阶段**（`execute` 执行前）：模型生成的参数根据编译后的 schema 进行值校验——类型匹配、必填键存在、`enum`/`const` 约束、`oneOf` 精确匹配、嵌套值递归校验。违反时抛出 **`ToolArgsError`**，错误信息包含路径限定的违规描述。

---

### 常见 Schema 校验问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 使用了 `anyOf` / `allOf` | 子集不支持，仅支持 `oneOf` | 改用 `oneOf` 重写 |
| 使用了 `pattern` / `format` / `minLength` 等 | 标量约束关键字不在子集内 | 去掉这些约束，或改用 `enum` 限定允许值 |
| `type` 声明为数组（如 `type: ['string', 'null']`） | 不支持类型数组 | 改用 `oneOf: [{ type: 'string' }, { type: 'null' }]` |
| `object` 缺少 `additionalProperties` | 必须显式声明 `additionalProperties: true/false` | 添加 `additionalProperties: false`（封闭）或 `true`（开放） |
| `required` 声明在 schema 节点上 | `required` 是属性级别的标记 | 在属性上添加 `required: true`（如 `path: { type: 'string', required: true }`） |
| `enum` 值类型不匹配声明 `type` | `enum` 值必须与 `type` 一致 | 确保 `enum` 中的值都是对应类型的实例 |

---

```ts

  description: '读取文件内容',
  parameters: {
    path: { type: 'string', description: '文件路径', required: true },

      type: 'string',
      enum: ['utf-8', 'ascii', 'base64'],
      description: '编码格式',
    },

    // args.path: string（已校验为 string 且必填）
```

# `defineTool` 完整用法：参数 Schema、输出投影与 UI 呈现

`defineTool` 是 `@deepseek-ai/dsh-tools` 导出的核心辅助函数，它一气呵成地完成 **schema 编译 → 类型推导 → 运行时校验 → 注册** 四件事。以下是逐字段拆解。

---

## 一、`defineTool` 完整签名

来自 [schema.ts#L482-L536](packages/core/tools/src/schema.ts#L482-L536)：

```ts
interface DefineToolOptions<S extends ParameterSchemaSpec, O extends ValueSchemaSpec> {
  name: string                         // 工具名（全局唯一）
  description: string                  // 给模型看的描述
  parameters: S                        // 参数 schema（隐式开放对象根）
  output: {                            // 输出规范
    schema: O                          //   输出值的 schema
    render(args, value): ContentBlock[]//   纯 Native/模型渲染
    presentationMeta?(args, value): JsonValue // 可重放的 UI 元数据
  }
  timeoutMs?: number                   // 协作超时（毫秒）
  isConcurrencySafe?(args): boolean    // 并发安全分类器
  execute(args, exec): Promise<InferValue<O>>  // 工具主体
  finalizeContent?(exec, result): ContentBlock[] | undefined  // 最后一程内容变换
  presentCall?(args): ToolCallView | undefined    // 调用中 UI 呈现
  presentResult?(args, result): ToolResultView | undefined  // 完成后 UI 呈现
}
```

---

## 二、参数 Schema：完整 DSL

`parameters` 是一个**隐式开放对象**，每个属性即一个参数，用 `required: true` 标记必填。支持的值类型节点如下：

### 标量类型

| 类型 | 允许的约束 | 示例 |
|------|-----------|------|
| `string` | `enum`, `const` | `{ type: 'string', enum: ['utf-8', 'ascii'] }` |
| `number` | `enum`, `const` | `{ type: 'number', const: 3.14 }` |
| `integer` | `enum`, `const` | `{ type: 'integer', enum: [1, 2, 3] }` |
| `boolean` | `enum`, `const` | `{ type: 'boolean' }` |
| `null` | `enum`, `const` | `{ type: 'null' }` |

### 容器类型

| 类型 | 必须声明 | 示例 |
|------|---------|------|
| `array` | 可选 `items` | `{ type: 'array', items: { type: 'string' } }` |
| `object` | **必须** `additionalProperties: boolean`，可选 `properties` | 见下文嵌套示例 |
| `json` | 无约束 | `{ type: 'json' }` — 接受任意无损 JSON |

### 联合类型

| 类型 | 规则 | 示例 |
|------|------|------|
| `oneOf` | 至少两个分支；不能与 `type` 同声明 | `{ oneOf: [{ type: 'string' }, { type: 'null' }] }` |

### 所有节点共享的注解

`description`, `title`, `default`, `examples` — 仅注解，**不参与校验**。

### ⛔ 不支持的关键字

`pattern`, `format`, `minLength`, `maxLength`, `minItems`, `maxItems`, `anyOf`, `allOf`, `$ref`, `minimum`, `maximum` 等。使用即抛 `JsonSchemaError`。

## 三、更丰富的 Schema 示例

### 嵌套对象 + 枚举 + oneOf

```ts
const searchTool = defineTool({
  name: 'search_code',
  description: '在代码库中搜索',
  parameters: {
    query: { type: 'string', description: '搜索关键词', required: true },
    scope: {
      type: 'object',
      additionalProperties: false,
      description: '搜索范围',
      properties: {
        paths: { type: 'array', items: { type: 'string' }, description: '限定目录' },
        languages: {
          type: 'array',
          items: { type: 'string', enum: ['ts', 'js', 'py', 'go'] },
          description: '限定语言',
        },
      },
    },
    target: {
      oneOf: [
        { type: 'string', description: '文件名模式' },
        { type: 'object', additionalProperties: false, properties: {
          glob: { type: 'string', required: true },
          caseSensitive: { type: 'boolean' },
        }},
      ],
      description: '搜索目标：字符串或 glob 对象',
    },
    limit: { type: 'integer', description: '最大结果数' },
  },
  // ... output & execute
})
```

类型推导结果：

```ts
args.query: string           // required
args.scope?: {               // optional
  paths?: string[]
  languages?: ('ts' | 'js' | 'py' | 'go')[]
}
args.target?: string | { glob: string; caseSensitive?: boolean }
args.limit?: number          // integer 推导为 number
```

---

## 四、输出规范 `output`

`output` 不只是 schema——它是**三件套**：

| 字段 | 类型 | 职责 |
|------|------|------|
| `schema` | `ValueSchemaSpec` | 声明返回值的结构，`execute` 的返回值会被校验 |
| `render` | `(args, value) → ContentBlock[]` | **纯面向模型**的渲染，将规范值投射为模型可读的内容块 |
| `presentationMeta` | `(args, value) → JsonValue`（可选） | **可重放的 UI 元数据**，持久化在 `tool/result` 事件中 |

核心原则：**`render` 是给模型看的，`presentationMeta` 是给 UI 看的，二者必须都是纯函数。**

```ts
output: {
  schema: {
    type: 'object',
    additionalProperties: false,
    properties: {
      lines: { type: 'array', items: { type: 'json' } },
      totalLines: { type: 'integer' },
    },
  },
  render(args, value) {
    // 模型看到的：带行号的文本
    return [{ type: 'text', text: value.lines.map(l => l.text).join('\n') }]
  },
  presentationMeta(args, value) {
    // UI 看到的：结构化行数据，可被 presentResult 回读
    return { path: args.path, offset: args.offset, lines: value.lines, totalLines: value.totalLines }
  },
}
```

## 五、UI 呈现：`presentCall` 与 `presentResult`

这是 `defineTool` 最精巧的部分。呈现分为**调用中**（pending）和**完成后**（result）两个阶段，各自返回一个 tagged union 视图，由 UI 桥接层映射到具体组件。

### `presentCall`：调用中呈现

返回 `ToolCallView`，三种卡片（[presentation.ts#L46](packages/core/tools/src/presentation.ts#L46)）：

| 卡片 | 用途 | 关键字段 |
|------|------|----------|
| `GenericCallView` (`card: 'generic'`) | 默认卡片：标题 + 图标 + 输入 + 文件位置 | `title`, `kind?`, `rawInput?`, `content?`, `locations?` |
| `TerminalCallView` (`card: 'terminal'`) | Shell 命令卡片：终端样式渲染 | `title`（命令）, `description?`, `cwd?` |
| `DiffCallView` (`card: 'diff'`) | 文件修改卡片：内联 diff 渲染 | `title`, `diffs: FileDiff[]`, `locations?` |

**`kind` 图标类别**：`'read' | 'edit' | 'delete' | 'move' | 'search' | 'execute' | 'fetch' | 'other'`

示例——`bash` 工具的调用呈现：

```ts
presentCall(args) {
  return {
    card: 'terminal',
    title: args.command,
    description: '执行 Shell 命令',
    cwd: args.cwd,
  }
}
```

示例——`write` 工具的 diff 呈现：

```ts
presentCall(args) {
  return {
    card: 'diff',
    title: `Write ${args.path}`,
    diffs: [{ path: args.path, oldText: null, newText: args.content }],
    locations: [{ path: args.path }],
  }
}
```

### `presentResult`：完成后呈现

返回 `ToolResultView`，六种卡片（[presentation.ts#L140](packages/core/tools/src/presentation.ts#L140)）：

| 卡片 | 用途 | 典型工具 |
|------|------|----------|
| `GenericResultView` (`card: 'generic'`) | 默认：替换标题 + 重组内容 | 通用 |
| `TerminalResultView` (`card: 'terminal'`) | 终端输出 + 退出码/信号 | `bash` |
| `DiffResultView` (`card: 'diff'`) | 已应用的文件变更 | `write`, `edit` |
| `SearchResultView` (`card: 'search'`) | 搜索结果：按文件分组匹配 or 路径列表 | `grep`, `glob` |
| `ReadResultView` (`card: 'read'`) | 行号 + 语法高亮代码视图 | `read` |
| `WebResultView` (`card: 'web'`) | 网页搜索/抓取结果 + 引用源 | `web_search`, `web_fetch` |

示例——`read` 工具的结果呈现：

```ts
presentResult(args, result) {
  const meta = result.presentationMeta as { path: string; offset: number; lines: ReadFileLine[]; totalLines: number }
  return {
    card: 'read',
    path: meta.path,
    offset: meta.offset,
    lines: meta.lines,
    totalLines: meta.totalLines,
    lang: inferLang(meta.path),  // 从扩展名推导
  }
}
```

### 呈现的**软校验**机制

关键设计：`presentCall` / `presentResult` 在**重放旧日志**时可能遇到与当前 schema 不兼容的旧参数。因此它们做**软校验**——validate 不通过时返回 `undefined`（退化为通用卡片），而不是抛错：

```ts
// schema.ts#L598-L608
tool.presentCall = (args: unknown): ToolCallView | undefined => {
  if (validate(args).length > 0) return undefined  // 软失败，退化为通用
  return userPresentCall(args as InferArgs<S>)
}
```

## 六、其他字段

| 字段 | 说明 |
|------|------|
| `timeoutMs` | 正有限数，协作超时预算（毫秒） |
| `isConcurrencySafe(args)` | 返回 `true` 表示此调用可加入并行组，不会被顺序化 |
| `finalizeContent(exec, result)` | 最后一程内容变换，对**所有**归一化结果（含校验失败）生效；可用于统一格式化错误输出 |

## 七、完整端到端示例

```ts
import { defineTool } from '@deepseek-ai/dsh-tools'
import type { ReadFileLine, ReadResultView } from '@deepseek-ai/dsh-tools/presentation'

const readTool = defineTool({
  name: 'read',
  description: '读取文件内容',
  parameters: {
    path:         { type: 'string',  description: '文件路径', required: true },
    offset:       { type: 'integer', description: '起始行号（1-based）' },
    limit:        { type: 'integer', description: '最大行数' },
  },
  output: {
    schema: {
      type: 'object',
      additionalProperties: false,
      properties: {
        lines:      { type: 'array',  items: { type: 'json' } },
        totalLines: { type: 'integer' },
      },
    },
    render(args, value) {
      const text = (value.lines as ReadFileLine[]).map(l => l.text).join('\n')
      return [{ type: 'text', text }]
    },
    presentationMeta(args, value) {
      return { path: args.path, offset: args.offset ?? 1, lines: value.lines, totalLines: value.totalLines }
    },
  },
  timeoutMs: 30_000,
  isConcurrencySafe(args) { return true },  // 只读，可并发

  presentCall(args) {
    return {
      card: 'generic',
      title: `Read ${args.path}`,
      kind: 'read',
      locations: [{ path: args.path, line: args.offset }],
    }
  },

  presentResult(args, result) {
    const meta = result.presentationMeta as { path: string; offset: number; lines: ReadFileLine[]; totalLines: number }
    return {
      card: 'read',
      path: meta.path,
      offset: meta.offset,
      lines: meta.lines,
      totalLines: meta.totalLines,
    } satisfies ReadResultView
  },

  async execute(args, exec) {
    // args.path: string（已校验必填）
    // args.offset?: number（已校验 integer）
    // args.limit?: number
    const content = await readFileContent(args.path, args.offset, args.limit)
    return { lines: content.lines, totalLines: content.totalLines }
  },
})
```

## 八、校验失败的行为总结

| 阶段 | 失败类型 | 抛出 | 行为 |
|------|---------|------|------|
| 定义时 | schema 包含不支持的关键字 | `JsonSchemaError` | 工具无法注册，插件加载失败 |
| 定义时 | `timeoutMs` 非正有限数 | `Error` | 同上 |
| 调用时 | 模型生成参数违反 schema | `ToolArgsError`（code `INVALID_ARGS`） | `execute` 不执行；错误进入模型上下文供重试 |
| 呈现时 | 重放旧参数与当前 schema 不兼容 | **不抛错** | 返回 `undefined`，退化为通用 UI 卡片 |
