## 会话日志与事件溯源：UI 渲染的数据源

会话日志是每次 Agent 交互的**仅追加、不可变的真实来源**。系统不在原地修改对话状态，而是将每个离散事件——用户提示词、模型分块、工具结果、轮次边界——作为 `SessionEvent` 条目记录在严格有序的日志中。

提交给 LLM 的消息历史是此日志上的**派生投影**。核心设计选择：**日志即真相；其余皆为视图**。

---

### 一、核心架构原则

| 原则 | 含义 |
|---|---|
| **仅追加** | 事件一旦追加不可修改、不可删除 |
| **不可变** | `deepFreeze()` 处理后发布，观察者无法篡改 |
| **严格有序** | 每个事件分配单调递增的 `seq` 和 `time` |
| **派生投影** | LLM 消息历史由 `deriveMessages()` 从日志重建，而非独立存储 |
| **模型可见即已记录** | 模型看到的任何内容都必须可从日志重建——运行时不变量 |

---

### 二、事件词汇表与 SessionEventMap

`SessionEventMap` 接口定义完整的事件词汇表——一种**核心拥有、插件可扩展**的合并可扩展求和类型。插件通过 TypeScript 声明合并添加自定义事件，无需修改核心。

#### 事件分类

| 类别 | 事件 | 持久化？ | 模型可见？ | 用途 |
|---|---|---|---|---|
| **持久表面事件** | `turn/*`、`step/*`、`user/message`、`assistant/*`、`tool/call`、`tool/result` | ✅ 追加到日志 | ✅ 进入 `deriveMessages()` 投影 | LLM 消息历史的重建基础 |
| **持久仅日志事件** | `sandbox/mode`、`approval/asked`、`approval/decided`、`permission/preset`、`todo/write`、`fs/observed`、`hook/*`、`tool/code-dispatch` | ✅ 追加到日志 | ❌ 永不出现在模型记录 | 审计、遥测、UI 状态，不污染模型上下文 |
| **实时扩展点** | `agent/pre-step`、`agent/request`、`llm/stream`、`tools/*` | ❌ 不持久化 | ❌ | waterfall 拦截，运行时策略 |

**持久与仅日志的区分是架构性的**：模型可见即已记录。

#### 核心表面事件详解

| 事件 | 载荷 | 投影行为 |
|---|---|---|
| `user/message` | 用户消息内容 | 直接映射为 `messages[]` 中的 `user` 条目 |
| `assistant/chunk` | SSE 流式分块 | 增量构建 `assistant` 消息；`BlockAssembler` 组装内容块 |
| `assistant/message` | 完整助手消息 | 完成的助手轮次 |
| `tool/call` | 工具名称、参数、callId | 映射为 `messages[]` 中的 `tool_calls` 条目 |
| `tool/result` | 冻结结果、callId | 映射为 `messages[]` 中的 `tool` 条目；通过 `sourceEventSeqs` 链接到 `tool/call` |
| `turn/start` / `turn/end` | 轮次边界 | 划分模型请求的边界 |
| `step/start` / `step/end` | 步骤边界 | 划分单次模型请求+工具执行的边界 |
| `session/end-seed` | 种子边界标记 | 区分重放历史与活跃工作 |

**每个 `tool/call` 事件与恰好一个 `tool/result` 事件配对**，即使对于跳过的调用也是如此。

---

### 三、追加路径（热路径）

`append()` 方法在一次递归遍历中完成所有工作：

```
event 进入 append()
    │
    ├── 验证 JSON 可序列化性
    ├── 分配 seq / time（单调递增）
    ├── deepFreeze(event)
    ├── 验证表面转换（状态机守卫）
    ├── 推入日志数组
    ├── 使缓存失效
    └── 发布给 session/event 观察者（emit 模式，即发即弃）
```

**热路径永不阻塞 I/O**——持久化插件异步缓冲。这是仅追加日志的"最终持久"语义与用户期望已完成工作能在崩溃中幸存之间的桥梁。

---

### 四、派生投影

#### deriveMessages() — LLM 消息历史

```typescript
deriveMessages(): Message[]
```

通过遍历有序表面投影重建 LLM 消息历史。**每个表面节点仅投影一次**（每次调用 O(新节点数)），利用缓存失效标记跳过已投影前缀。

```
SessionEvent 日志
    │
    ├── user/message        →  { role: 'user', content: ... }
    ├── assistant/message   →  { role: 'assistant', content: ..., tool_calls: ... }
    ├── tool/call           →  映射到 assistant.tool_calls[]
    ├── tool/result         →  { role: 'tool', tool_call_id: ..., content: ... }
    │
    └── 仅日志事件          →  跳过（不进入投影）
```

#### session-stats — 聚合读模型

`session-stats` 从日志中投影聚合统计信息（令牌使用量、轮次计数、工具调用频率）——**永不修改源事件**的读模型。

#### session-title — 标题派生

`session-title` 为会话派生人类可读的标题，其可插拔提供者（首条提示词启发式、基于 LLM 的摘要）将事件日志作为输入消费。

---

### 五、SessionHeader 与 Session 生命周期

`SessionHeader` 携带存在于事件日志**之外**的不可变存储元数据——它是存储关注点，不是事件溯源关注点。

| 字段 | 用途 |
|---|---|
| `sessionId` | 唯一标识符 |
| `createdAt` | 创建时间戳 |
| `rootDir` | 会话工作区根目录 |
| `presetId` | 使用的 Agent 预设 |

#### 生命周期

```
创建 ──▶ 活跃（追加事件）──▶ 释放
  │                          │
  │ fromRestore()            │ dispose()
  ▼                          ▼
恢复（从存储日志种子）     销毁（清理内存）
```

**关键约束**：Agent 工厂需要将生命周期与 Agent 循环一起折叠为**单个有序副作用**，以便在纤程拆解时将两者作为链条而非竞争的同级副作用一起销毁。如果会话在循环最终事件提交前分离，这些事件将被静默丢弃。

### 六、持久化：插件关注点

**存储本身不实现 I/O**。持久化是插件关注点，遵循双事件协议：

| 事件 | 模式 | 用途 |
|---|---|---|
| `session/event` | emit | 即发即弃追加流——每条新事件实时通知 |
| `session/flush` | parallel | 等待持久性检查点——所有持久化/遥测监听器并发运行 |

**持久化插件的工作模式**：

```typescript
// 持久化插件伪代码
ctx.on('session/event', (event) => {
  buffer.push(event)  // 缓冲，不阻塞热路径
})

ctx.on('session/flush', async () => {
  await backend.flush(buffer)  // 排空到后端
  buffer.clear()
})
```

这种分离保持了**热追加路径的非阻塞特性**，同时赋予后端对批处理、压缩和崩溃安全的完全控制。

检查点策略根据轮次边界、步骤完成或时间阈值来决定——不会在每次追加时排空（开销过大）。

---

### 七、分叉、恢复与崩溃恢复

事件溯源架构使日志级操作成为轻量操作：

#### 分叉

```
源会话: [e0, e1, e2, e3, ...]
                       │
                       ▼ 分叉点
新会话: [e0, e1, e2, e3]  +  session/end-seed  +  后续新事件
```

- 使用源会话事件前缀作为种子创建新会话
- `session/end-seed` 事件标记种子边界
- `firstLiveSeq = seedLength`，标记当前进程中追加的第一个序列号

#### 恢复

- 进程重启时，持久化后端加载完整存储日志作为种子
- `Session.fromRestore()` 静态构造器接管新的持久化值（就地验证、冻结而不复制）
- 会话从 `log.length` 处继续追加
- `firstLiveSeq` 使遥测从正确位置发布，无需重新发射历史事件

#### 崩缩（压缩）

- 崩溃恢复和压缩都重写日志前缀
- 已提交的事件不可逆——日志是真实来源，观察者是投影

### 八、版本兼容与 ignorable 守卫

日志是持久化的，可能跨越版本升级：

| 变更类型 | 是否递增版本？ | 处理方式 |
|---|---|---|
| 添加新事件类型 | 否 | `ignorable` 守卫覆盖词汇表增长 |
| 信封/头信息结构变更 | 是 | 较旧运行时无法解析 → 版本检查 |
| 表面机制结构性变更 | 是 | "解析无错" ≠ "正确性" |

在追加点将事件的 `ignorable` 设为 `true`，以便较旧运行时安全跳过。将版本递增保留给结构性变更。

### 九、沙箱/审批的事件溯源集成

会话级别的策略覆盖作为**事件存储在会话日志中**——没有外部配置存储：

```typescript
setSandboxMode(session, mode)  // 恰好追加一个事件
```

有效模式是折叠结果：`effective = last(events) ?? deploymentDefault`

| 属性 | 含义 |
|---|---|
| 通过重播在重启后存活 | 日志持久化，无需追赶机制 |
| 会话隔离 | 两个会话永不见彼此的覆盖 |
| 仅日志 | 从不出现在模型记录中；模型通过运行时上下文快照学习策略 |

**回合封闭**：`approval/asked` + `approval/decided` 对是回合封闭的——回合是持久日志的提交/重播边界。回合之间的裸事件在重新加载时是崩溃尾部的垃圾数据，会被静默丢弃。空闲的询问（无开放回合）在追加任何内容之前拒绝。

### 十、UI 渲染数据流

UI 从 `session/event` 流驱动渲染的完整路径：

```
┌─ Session 日志（真实来源）───────────────────────────────┐
│                                                         │
│  [e0] session/header                                    │
│  [e1] turn/start                                       │
│  [e2] step/start                                       │
│  [e3] user/message         ──→ UI: 用户消息气泡         │
│  [e4] assistant/chunk      ──→ UI: 流式渲染助手回复     │
│  [e5] tool/call            ──→ UI: presentCall() 待定卡片│
│  [e6] tool/result          ──→ UI: presentResult() 完成卡片│
│  [e7] step/end                                         │
│  [e8] turn/end                                         │
│  [e9] sandbox/mode        ──→ UI: 策略指示器更新        │
│                                                         │
├─ 派生投影 ─────────────────────────────────────────────┤
│                                                         │
│  deriveMessages()  → LLM 消息历史（模型可见）           │
│  session-stats     → 聚合统计（Token、轮次、工具频率）   │
│  session-title     → 人类可读标题                       │
│                                                         │
├─ 持久化管线 ───────────────────────────────────────────┤
│                                                         │
│  session/event → 缓冲 → session/flush → 后端排空       │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**UI 模块消费模式**：

| UI 模块 | 数据源 | 渲染方式 |
|---|---|---|
| `ui-conversation` | `session/event` 流 | 按序渲染消息气泡、工具卡片、轮次边界 |
| `ui-tool` | `tool/call` + `tool/result` 对 | 按 `callId` 配对待定/完成卡片 |
| `ui-workflow-run` | `tool-workflow/run-start` + `run-end` | 会话节点引擎折叠为 `workflow-run` 聊天节点 |
| `ui-settings` | 设置事件 + `session/event` | 策略/配置状态 |

**重放安全**：同一 `presentCall`/`presentResult` 函数在实时流和日志重放时运行——这是事件溯源对 UI 的直接保证。
