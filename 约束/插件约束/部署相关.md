## 包与配置档案：工具如何组合为可部署的 Agent 配置

DeepSeek Harness 的运行时由**三层抽象**组合而成，从底层到顶层依次为：

```
Bundle（包）  →  Profile（配置档案）  →  Preset（预设）
部署时复用层      进程级组合层           会话级 Agent 身份层
```

---

### 一、Bundle — 可复用的插件行补丁层

**Bundle 的实质就是它的补丁列表**。每个 bundle 是一个 Cordis 配置行及其挂载代码的分发格式，以 `cordis.patch.yml` 为载体：

```yaml
# packages/bundle/base/cordis.patch.yml
- id: llm-deepseek
  name: '@deepseek-ai/dsh-llm-deepseek'
  config: { ... }
- id: tool-bash
  name: '@deepseek-ai/dsh-tool-bash'
- id: tool-fs
  name: '@deepseek-ai/dsh-tool-fs'
- id: session-sqlite
  name: '@deepseek-ai/dsh-session-sqlite'
# ... 更多行
```

**三个内置 bundle**：

| Bundle | 职责 | 内容 |
|---|---|---|
| `dsh-base` | 核心层——每个 profile 的第一层 | 模型适配器、工具、持久化、沙箱与审批策略、设置、凭证、遥测、Agent 循环、系统提示词、作用域 |
| `dsh-web-app` | 模式层——浏览器应用 | Web 服务器、React UI、RPC 连接 |
| `dsh-headless` | 模式层——无头 CLI | 一次性非交互 Agent 驱动器 |

`dsh-base` 的 `cordis.patch.yml` 是项目中最大的单一组合文件。

**关键属性**：
- manifest 声明（而非目录位置）定义了 bundle 的身份
- 领域包可以携带各自可选的 bundle 层（Codex 和 Claude Code 子 Agent 包就是此模式的直接可安装示例）
- 某些 bundle 也会附带执行启动粘合逻辑的运行时插件，但组合机制从不区分二者
- bundle 插入的每一行都可以被上层的补丁修改——**整个运行时无需派生（fork）即可完成配置**

---

### 二、Profile — 有序 Bundle 组合加用户补丁

**Profile** 是位于 `$DSH_HOME/profiles/<name>` 下的一个目录（Harness 主目录通过 `resolveDshHome` 解析：`$DSH_HOME`，否则为 `~/.dsh`），包含：

| 文件 | 用途 |
|---|---|
| `profile.yml` | 有序 bundle 列表 + profile 元数据 |
| `cordis.patch.yml` | 用户级补丁覆盖（热重载） |

#### 层组合顺序

组合引擎在**空条目列表**上按严格顺序应用补丁层，对每个行 ID 实行**后写覆盖**：

```
Empty entry list
    │
    ▼ Bundle 1 patch (dsh-base)
    │  插入：LLM 适配器、工具、持久化、沙箱...
    ▼
    │ Bundle 2 patch (dsh-web-app 或 dsh-headless)
    │  插入：UI 或 CLI 入口；可覆盖 base 中的行
    ▼
    │ Bundle N patch (附加 bundle)
    │  更多领域包
    ▼
    │ Profile cordis.patch.yml
    │  用户按配置覆盖（热重载）
    ▼
    │ Home cordis.patch.yml (~/.dsh/cordis.patch.yml)
    │  主目录级覆盖
    ▼
    │ --patch CLI overlay
    │  调用级覆盖
    ▼
  Final composed entry list
```

**两个内置 profile**：

| Profile | 组合 | 用途 |
|---|---|---|
| `web` | `dsh-base` + `dsh-web-app` | 完整的浏览器应用 |
| `headless` | `dsh-base` + `dsh-headless` | 一次性非交互 Agent |

启动命令：
```sh
dsh web                                    # --profile web 的别名
dsh --profile headless "task"              # 运行单个任务
dsh --profile web --dump-config            # 检查组合后的插件树
dsh plugin --profile <name> add <package>  # 创建自定义 profile
```

#### 用户补丁层

Profile 的 `cordis.patch.yml` 是一个顶层加载器补丁条目的 YAML 数组。补丁通过 ID 定位一个配置行并**替换其整个配置**，或插入新行：

```yaml
# ~/.dsh/profiles/web/cordis.patch.yml
- id: llm-deepseek                    # 覆盖 base 中同名行的配置
  config:
    model: deepseek-chat-v3
- id: my-custom-tool                  # 插入新行
  name: './my-tool.ts'
```

### 三、Preset — 每次会话的 Agent 组合

当 bundle 和 profile 组合**进程级**插件树时，**Agent 预设**则组合**每次会话**的 Agent 身份——它的工具、提示词片段和人设。

#### 预设结构

每个预设是一个目录，包含：

| 文件 | 用途 |
|---|---|
| `agent.cordis.yml` | 组合文件——Cordis 条目列表 |
| `preset.yml` | 可选元数据（显示名、描述、信任级别） |

目录名即为预设 id。

#### 驻留挂载（Standing Mount）

`ctx.agentPresets.mount()` 通过确保预设的**驻留挂载**——一个单次执行、作用域隔离的子树——并将 Agent 的作用域键定位于其上来组合一个 Agent。

```
┌─ Standing Mount (once per preset) ──────────────┐
│  Preset Scope (agent.cordis.yml)                 │
│    ├── tool-bash                                 │
│    ├── tool-fs                                   │
│    └── persona: "standard agent"                 │
└──────────────────────────────────────────────────┘
        │                    │
        ▼                    ▼
┌─ Session A ──────┐  ┌─ Session B ──────┐
│  scope joins     │  │  scope joins     │
│  per-session key │  │  per-session key │
└──────────────────┘  └──────────────────┘
```

**驻留挂载实现每次会话组合的关键**：
- 入口上下文链接到子树插入的上下文
- 工具和系统提示词注册归入调用上下文的作用域层
- 挂载的贡献**精确地到达**加入它的 Agent

**两个隔离守卫**：
1. 从未达到可用状态的行会被拒绝（启动审计不覆盖直接插入的子树）
2. 将服务发布到**根领域**的行也会被拒绝（这样的服务将是进程全局的，跨会话发生冲突）

当创建 Agent 时，其作用域键通过 `bindScopeParent` **父级化**到常驻挂载的作用域键——同一预设的多个会话共享相同的插件实例，同时在插件内部保持按会话键控的状态。

#### 人设 — 每个预设的身份

`dsh-persona` 包将 Agent 人设作为可组合的行提供，允许预设为一个 Agent 作用域**遮蔽**部署的默认人设：

```yaml
# agent.cordis.yml
- id: persona
  name: '@deepseek-ai/dsh-persona'
  config:
    text: "You are a minimal coding agent..."
    complete: false          # true = 独占系统提示词
    includeRuntimeContext: true  # 包含动态运行时上下文快照
```

**关键**：Agent 作用域遮蔽部署的默认人设。在 Agent 作用域之外挂载此行会与注册表自身的 `deployment:persona` 注册发生冲突并 loudly 报错——部署人设已经拥有所有者，而此行的全部意义就是为一个 Agent 遮蔽它。

#### 内置预设

| Preset | 显示名 | 描述 |
|---|---|---|
| `standard` | Standard | 完整工具集 + 标准人设 |
| `minimal` | Minimal | 最小工具集 (bash, str_replace_editor) + 精简人设 |

### 四、Profile vs Preset — 何时用哪个

| 维度 | Profile | Preset |
|---|---|---|
| **作用域** | 进程级：决定哪些插件加载 | 会话级：决定 Agent 看到哪些工具/提示词 |
| **内容** | 有序 bundle 列表 + 用户补丁 | 每个 Agent 的 `agent.cordis.yml` |
| **变更时机** | 启动时；更改需重启（HMR 打补丁的 `cordis.patch.yml` 除外） | 每次会话；新会话立即采用新预设 |
| **典型用途** | 在 Web/无头模式之间切换 | 选择工具集、人设、提示词片段 |
| **配置文件** | `$DSH_HOME/profiles/<name>/profile.yml` | `apps/cli/config/agent-presets/<name>/` |

### 五、全组合一览

将三层放在一起，从空列表到运行时：

```
┌──────────────────────────────────────────────────────────┐
│  Bundle 层（部署时）                                       │
│    dsh-base → dsh-web-app / dsh-headless → 领域 bundle    │
│    每个 bundle 的 cordis.patch.yml 依次叠加               │
├──────────────────────────────────────────────────────────┤
│  Profile 层（进程级）                                      │
│    Profile cordis.patch.yml → Home cordis.patch.yml       │
│    → --patch CLI overlay                                  │
│    结果：进程级插件树（哪些插件存在）                        │
├──────────────────────────────────────────────────────────┤
│  Preset 层（会话级）                                       │
│    agent.cordis.yml → 驻留挂载 → 作用域隔离               │
│    结果：每次会话的 Agent 身份（哪些工具/提示词/人设）        │
├──────────────────────────────────────────────────────────┤
│  Settings 层（运行时，热重载）                              │
│    Schema 默认值 → 组合 base → 用户层                      │
│    结果：即时生效的用户配置，无需重启                         │
└──────────────────────────────────────────────────────────┘
```

**后写覆盖**贯穿所有层：同一 ID 的行，后层替换前层的整个配置。这使得整个运行时可以在不派生代码的情况下完成定制。
