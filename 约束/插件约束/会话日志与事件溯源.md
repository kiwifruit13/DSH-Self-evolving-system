## 会话日志与事件溯源：深度解析

整个架构围绕一个激进的设计选择展开：**日志即真相；其余皆为视图**。这意味着系统从不原地修改对话状态，而是将每个离散事件作为不可变条目追加到严格有序的日志中。

---

### 一、核心数据结构：Session 类

`Session` 是一个仅追加的事件日志容器，定义在 [index.ts](packages/core/session/src/index.ts#L425-L548)：

```
Session
├── log: SessionEvent[]          // 私有，仅追加数组
├── header: SessionHeader        // 不可变存储元数据（格式版本、cwd、分叉谱系等）
├── firstLiveSeq: number         // 本进程首次追加的位置（区分种子重放与活跃写入）
├── surfaceManager               // 表面投影的增量维护器
├── events                       // 公开只读快照（缓存 + Object.freeze）
└── seq                          // = log.length（序列号连续性契约）
```

**不可变性保证**：所有事件及其嵌套数据在进入日志时被 `deepFreeze()` 深度冻结——类型转换或普通 JavaScript 都无法改写持久历史。

---

### 二、事件词汇表：SessionEventMap

`SessionEventMap` 接口定义了完整的事件类型到负载的映射，是一个**合并可扩展求和类型**（merge-extensible sum type）——核心拥有基础词汇，插件通过 TypeScript declaration merging 扩展。

源码定义见 [types.ts](packages/core/session/src/types.ts#L236-L337)：

| 事件类型 | 负载 | 表面事件？ | 用途 |
|---|---|---|---|
| `turn/start` | `{ turn }` | ✗ | 打开一个轮次 |
| `turn/end` | `{ turn, reason }` | ✗ | 关闭轮次（含终止原因：completed/aborted/error/max-tokens/interrupted） |
| `step/start` | `{ turn, step }` | ✗ | 打开一个步骤（一次模型调用 + 工具执行） |
| `step/end` | `{ turn, step }` | ✗ | 关闭步骤 |
| `user/message` | `UserMessage` | ✓ | 用户消息（直接提示词、`agent.inject()` 上下文、目标续轮） |
| `assistant/chunk` | `{ turn, step, chunk }` | ✗ | 原始流式分块（token 级重放保真） |
| `assistant/message` | `{ turn, step, message, usage?, interrupted? }` | ✓ | 步骤组装后的助手消息 |
| `tool/call` | `{ turn, step, callId, name, arguments }` | ✗ | 模型请求的工具调用 |
| `tool/result` | `{ turn, step, message, error?, meta? }` | ✓ | 工具执行结果（meta 为工具私有展示负载） |
| `todo/write` | `{ todos }` | ✗ | 待办列表全量快照（最新写入胜出） |
| `request/header` | `{ header, reason }` | ✗ | 请求头快照（config + system prompt + tools） |
| `request/context` | `RequestContext` | ✗ | 路由元数据（provider/model/contextWindow） |
| `session/end-seed` | `Record<string, never>` | ✗ | 种子边界标记（区分重放历史与活跃工作） |

**表面事件**（`user/message`、`assistant/message`、`tool/result`）是唯一进入派生消息历史的事件类型，必须在 `append()` 时提供 `SurfaceIntent`（含 `surfaceOp` 和 `sourceEventSeqs`）；非表面事件在编译时拒绝该参数。

### 三、事件信封结构

每个 `SessionEvent` 是一个判别联合（discriminated union），`switch (event.type)` 可直接窄化 `event.data`：

```typescript
SessionEvent = {
  type: K                    // 判别式
  seq: number                // 单调序列号 = log 索引位置
  time: number               // Unix 纪元毫秒
  data: SessionEventMap[K]   // 强类型负载
  ignorable?: true           // 前向兼容标记
  // 以下仅表面事件存在：
  sourceEventSeqs?: number[] // 引用的源事件 seq 集合
  surfaceOp?: SurfaceOp      // 'append' | { op: 'replace', start, end }
}
```

**`ignorable` 字段**实现了前向兼容的词汇表增长：未识别的事件若无此标记，读取器必须拒绝重建会话；有此标记则可安全跳过。添加普通事件类型**不需要**递增 `SESSION_FORMAT_VERSION`——`ignorable` 守卫覆盖了词汇表增长；只有信封/头信息/表面机制的结构性变更才需要递增。

### 四、追加路径（`Session.append()`）

核心写入路径在 [index.ts](packages/core/session/src/index.ts#L569-L599)，流程如下：

```
append(type, data, opts?)
  │
  ├─ 1. 一次性递归验证 + JSON 快照
  │     (snapshotJsonValue: 拒绝 BigInt/symbol/undefined/循环引用/稀疏数组等)
  │
  ├─ 2. 验证表面元数据
  │     (SurfaceEventType 必须提供 surfaceOp + sourceEventSeqs;
  │      非表面事件编译时拒绝)
  │
  ├─ 3. SurfaceManager.validateNext()
  │     (检查表面转换合法性：append/replace 位置、源事件覆盖)
  │
  ├─ 4. deepFreeze(event) → push to log
  │     (seq = log.length, time = Date.now())
  │
  ├─ 5. 失效 eventsSnapshot 缓存
  │
  └─ 6. 发布 session/event (fire-and-forget)
        (观察者失败按监听器隔离，不阻止其他监听器)
```

**关键属性**：热追加路径**永不阻塞 I/O**——持久化插件异步缓冲，`append()` 同步返回已冻结的事件。

### 五、派生投影与表面机制

提交给 LLM 的消息历史不是日志本身，而是日志上的**派生投影**——由有序表面事件重建而成：

```
事件日志（仅追加真相）
    │
    ▼ SurfaceManager（增量维护）
有序表面 = [user/msg₀, assistant/msg₀, tool/result₀, assistant/msg₁, ...]
    │
    ▼ deriveEventMessage()
LLM 消息历史（给模型的请求负载）
```

**表面操作**（`SurfaceOp`）：
- `'append'`：追加到尾部——正常消息路径
- `{ op: 'replace', start, end }`：替换表面节点 [start, end]——用于压缩（compaction），被替换节点的 `sourceEventSeqs` 必须包含所有被覆盖的节点

这种分离使压缩可以重写表面而不改变底层日志——日志始终完整，表面是可变视图。

### 六、分叉、恢复与崩溃恢复

事件溯源架构使日志级操作变得轻量：

**分叉**：使用源会话事件前缀作为种子创建新会话。
```typescript
const forked = ctx.sessions.create(SessionId('new'), { seed: parentSession.events })
```

**恢复**：构造器种子是完整的存储日志；`firstLiveSeq` 标记当前进程首次追加位置。

**崩溃恢复**：
- 如果会话在轮次最终事件提交前分离，中间事件被静默丢弃
- 回合间（turn 之间）的裸事件在重新加载时是崩溃尾部垃圾数据，被静默丢弃
- `session-checkpoint-policy` 拥有每请求的持久性检查点，确保崩溃后可恢复到最近一致状态

**种子边界**（`session/end-seed` 事件）：
- 构造器自动追加，区分重放历史与活跃工作
- 重新打开未修改的会话不会增长日志（已有边界不再重复标记）
- 定位存储历史中的**最后一个** `session/end-seed`——它未必在 `firstLiveSeq` 处

### 七、持久化：插件关注点

持久化本身不实现 I/O，而是通过两个事件完成分离：

| 事件 | 模式 | 用途 |
|---|---|---|
| `session/event` | emit（即发即弃） | 持久化插件订阅此追加流，异步缓冲写入 |
| `session/flush` | parallel（等待全部完成） | 调用方等待持久性检查点，排空缓冲 |

```
session/event ──(即发即弃追加流)──▶ 持久化插件 ──(缓冲)──▶ Durable Storage
session/flush ──(await all)────────▶ 持久化插件 ──(排空)──▶ Durable Storage
```

这种分离保持了热追加路径的**非阻塞特性**，同时赋予后端对批处理、压缩和崩溃安全的完全控制。

---

### 八、投影注册表（CQRS 读模型）

**`session-projection`** 定义了一个注册表，插件在其中注册事件日志上的命名投影。每个投影增量接收事件并维护自己的派生状态——一种经典的 CQRS 读模型：

| 投影 | 包 | 作用 |
|---|---|---|
| 聚合统计 | `session-stats` | 令牌使用量、轮次计数、工具调用频率 |
| 会话标题 | `session-title` | 人类可读标题（首条提示词启发式 / LLM 摘要） |
| 缓存层 | `session-projection-cache` | 日志未增长时跳过重复计算 |

**`session-telemetry`** 协调事件的脱敏与转发至遥测接收器；**`session-telemetry-otel`** 将流桥接至 OpenTelemetry 跨度和指标。

---

### 九、作用域过滤分发

Agent 作用域的监听器**仅接收**载体与该作用域或其后代匹配的事件——多 Agent 进程的工具策略独立运行，无交叉污染。

观察者失败被**隔离在每个监听器内**：抛出异常的回调会被记录，但无法阻止其他监听器观察同一事件。

---

### 十、已提交事件不可逆

这是架构的铁律：日志是真实来源，观察者是投影。一旦 `append()` 返回，事件就进入了不可变历史——没有任何 API 可以删除、修改或重排已提交事件。唯一改变表面的方式是追加一个 `surfaceOp: 'replace'` 的新事件。
