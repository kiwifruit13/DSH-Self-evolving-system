以下是项目中全部事件钩子及其对应注册接口的系统梳理。

---

## 一、持久会话事件（追加到日志，重载后保留）

这些事件通过 `SessionEventMap` 声明，由 `session.append()` 写入，注册监听使用 `ctx.on(event, listener)`。

| 事件类型 | 负载摘要 | 注册接口 |
|---|---|---|
| `turn/start` | `{ turn }` | `ctx.on('turn/start', fn)` |
| `turn/end` | `{ turn, reason }` | `ctx.on('turn/end', fn)` |
| `step/start` | `{ turn, step }` | `ctx.on('step/start', fn)` |
| `step/end` | `{ turn, step }` | `ctx.on('step/end', fn)` |
| `user/message` | `UserMessage`（表面事件） | `ctx.on('user/message', fn)` |
| `assistant/chunk` | `{ turn, step, chunk }` | `ctx.on('assistant/chunk', fn)` |
| `assistant/message` | `{ turn, step, message, usage?, interrupted? }`（表面事件） | `ctx.on('assistant/message', fn)` |
| `tool/call` | `{ turn, step, callId, name, arguments }` | `ctx.on('tool/call', fn)` |
| `tool/result` | `{ turn, step, message, error?, meta? }`（表面事件） | `ctx.on('tool/result', fn)` |
| `todo/write` | `{ todos }` — 全列表快照 | `ctx.on('todo/write', fn)` |
| `request/header` | `{ header, reason }` | `ctx.on('request/header', fn)` |
| `request/context` | `RequestContext` | `ctx.on('request/context', fn)` |
| `session/end-seed` | `Record<string, never>` — 种子边界标记 | `ctx.on('session/end-seed', fn)` |

> 源码定义：[types.ts](packages/core/session/src/types.ts#L236-L337)

---

## 二、Agent 实时事件（不持久化，waterfall 模式需调 `next()`）

| 事件类型 | 派发模式 | 用途 | 注册接口 |
|---|---|---|---|
| `agent/pre-step` | waterfall | 步骤前拦截/修改 | `ctx.on('agent/pre-step', fn)` |
| `agent/request` | waterfall | 请求拦截/转换 | `ctx.on('agent/request', fn)` |
| `agent/status` | emit | Agent 状态变更通知 | `ctx.on('agent/status', fn)` |
| `agent/disposed` | emit | Agent 销毁 | `ctx.on('agent/disposed', fn)` |
| `agent/turn-stopping` | waterfall | 轮次停止拦截 | `ctx.on('agent/turn-stopping', fn)` |
| `agent/inbox/spliced` | emit | 收件箱消息增删 | `ctx.on('agent/inbox/spliced', fn)` |
| `agent/error` | emit | Agent 级别错误 | `ctx.on('agent/error', fn)` |
| `agent/session-start` | emit | 会话生命周期开始 | `ctx.on('agent/session-start', fn)` |
| `agent-preset/selected` | emit | 预设选择应用 | `ctx.on('agent-preset/selected', fn)` |

> 扩展声明通过 TypeScript declaration merging：[types.ts](packages/core/agent/src/types.ts#L12-L27)；分发实现：[dispatch.ts](packages/core/agent/src/dispatch.ts#L122-L150)

## 三、能力接缝事件（横切关注点）

| 事件类型 | 声明包 | 用途 | 注册/挂载接口 |
|---|---|---|---|
| `fs/write` | `dsh-fs` | 文件系统写入：门控或转换 | `ctx.fs` 提供者注册 + `ctx.on('fs/write', fn)` |
| `fs/edit-intent` | `dsh-fs` | 文件编辑意图：门控或转换 | `ctx.on('fs/edit-intent', fn)` |
| `fs/observed` | `dsh-fs` | 文件系统观察记录 | `ctx.on('fs/observed', fn)` |
| `tools/change` | `dsh-tools` | 工具注册表变更 | `ctx.on('tools/change', fn)` |
| `tools/pre-execute` | `dsh-tools` | 工具执行前拦截（waterfall） | `ctx.on('tools/pre-execute', fn)` |
| `tools/result` | `dsh-tools` | 工具执行结果 | `ctx.on('tools/result', fn)` |
| `llm/stream` | `dsh-llm` | LLM 流式响应拦截（waterfall） | `ctx.llm` 适配器注册 |
| `sandbox/mode` | `dsh-sandbox` | 沙箱模式切换（仅日志审计） | `ctx.sandbox` 后端注册 |
| `approval/*` | `dsh-approval` | 审批决策（仅日志审计） | `ctx.on('approval/*', fn)` |
| `session-telemetry/record` | `session-telemetry` | 遥测记录：拦截或扩充 | `ctx.on('session-telemetry/record', fn)` |

> **重要**：`tools/pre-execute` 的拒绝可被监听器重排规避；安全关键拒绝应注册为**守卫**（monotonic guard），见 [工具执行流水线](13-tool-execution-pipeline)。

## 四、会话生命周期事件（parallel / emit 模式）

| 事件类型 | 派发模式 | 用途 | 注册接口 |
|---|---|---|---|
| `session/created` | emit | 新会话创建 | `ctx.on('session/created', fn)` |
| `session/disposed` | emit | 会话销毁 | `ctx.on('session/disposed', fn)` |
| `session/event` | emit | 即发即弃追加流（持久化插件订阅此流） | `ctx.on('session/event', fn)` |
| `session/flush` | parallel | 等待持久性检查点 | `ctx.on('session/flush', fn)` |
| `domain/changed` | emit | 存储域切换 | `ctx.on('domain/changed', fn)` |

---

## 五、子代理与工作流事件

| 事件类型 | 用途 | 注册接口 |
|---|---|---|
| `subagent/start` | 子代理启动 | `ctx.subagents.register(provider)` |
| `subagent/end` | 子代理结束 | `ctx.on('subagent/end', fn)` |
| `workflow/*` | 工作流编排事件（含 `seq` 顺序与阶段分组） | `ctx.workflowEngine` 注册 |

---

## 六、Hook 协议事件（仅日志，turn 内封闭）

| 事件类型 | 用途 | 注册接口 |
|---|---|---|
| `hook/invoked` | 钩子调用记录 | `session.append('hook/invoked', ...)` — 由框架内部写入 |
| `hook/result` | 钩子结果记录（含 `decision`、`exitCode`、`stderrSummary`、`durationMs`） | `session.append('hook/result', ...)` — 由框架内部写入 |

> 源码：[events.ts](packages/hooks/hook-protocol/src/events.ts#L75-L104)；Hook 桥接配置（Claude Code / Codex）位于 `packages/hooks/hooks-claude-code/` 和 `packages/hooks/hooks-codex/`。

---

## 七、内部框架事件（非公共接口）

| 事件类型 | 用途 |
|---|---|
| `internal/update` | HMR / 持久化钩子瀑布事件，可否决或转换更新 |
| `internal/dispatch` | Cordis 诊断事件（绕过作用域过滤） |

---

## 八、服务注册接口汇总

| 接口 | 用途 | 对应事件域 |
|---|---|---|
| `ctx.on(event, listener)` | 通用事件监听器注册 | 所有事件 |
| `ctx.agents` / `ctx.agents.get(id)` | Agent 注册表与句柄 | `agent/*` |
| `ctx.tools.register(...)` | 工具模式注册 | `tools/*` |
| `ctx.llm` | LLM 适配器注册 | `llm/*` |
| `ctx.fs` | 文件系统提供者注册 | `fs/*` |
| `ctx.shell` | Shell 执行后端注册 | — |
| `ctx.sandbox` | 沙箱后端注册 | `sandbox/*` |
| `ctx.subagents.register(provider)` | 子代理命名提供者注册 | `subagent/*` |
| `ctx.workflowEngine` | 工作流引擎注册 | `workflow/*` |
| `agent.inject()` | 注入面向模型的上下文 | 下一请求生效 |

> 所有 `ctx.on()` 注册在插件卸载时自动清理，无需手动 `ctx.effect()`——见 [插件生命周期与副作用](8-plugin-lifecycle-and-effects)。
