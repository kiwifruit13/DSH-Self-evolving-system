# Python 项目封装到 DSH 插件生态的完整路径

Python 项目接入 DeepSeek Harness 有**两条正交通路**，选择取决于你的意图：

| 路径 | 意图 | 通信协议 | 入口 |
|------|------|----------|------|
| **ACP 子 Agent** | Python 项目作为**独立 Agent**，被 Harness 主 Agent 派生调度 | JSON-RPC over stdio | `subagent-acp` 提供者 |
| **Python SDK 客户端** | Python 程序**驱动** Harness（无 UI 自动化） | JSON-RPC over stdio | `deepseek-harness-sdk` |

架构全貌：

```
Python 进程 ←→ JSON-RPC stdio ←→ ACP Bridge (Cordis 插件) ←→ Harness Agent Core
```

---

## 路径一：Python 项目作为 ACP 子 Agent

这是将 Python 项目**封装为 DSH 插件**的主流方式。你的 Python 项目实现 ACP 协议，Harness 通过 `subagent-acp` 提供者将其作为子 Agent 派生。

### 1. 实现 ACP 协议

ACP 协议要求实现四个方法（基于 JSON-RPC over stdio）：

| 方法 | 方向 | 作用 |
|------|------|------|
| `initialize` | Python → Harness | 声明能力、工具列表、模型偏好 |
| `prompt` | Harness → Python | 传入用户消息，触发 Agent 执行 |
| `requestPermission` | Harness → Python | 审批工具调用的权限请求 |
| `cancel` | Harness → Python | 取消进行中的执行 |

### 2. Python 端实现骨架

```python
# my_agent.py
import sys
import json

def handle_initialize(params):
    return {
        "tools": [
            {
                "name": "my_python_tool",
                "description": "我的 Python 工具",
                "parameters": {
                    "type": "object",
                    "properties": {
                        "input": {"type": "string", "description": "输入"}
                    },
                    "required": ["input"]
                }
            }
        ],
        "modelPreferences": {},  # 可选：声明模型偏好
    }

def handle_prompt(params):
    messages = params["messages"]
    tools = params.get("tools", [])
    # ... 你的 Agent 逻辑 ...
    return {
        "role": "assistant",
        "content": "处理结果",
        "toolCalls": [],  # 如果需要调用工具
    }

def handle_request_permission(params):
    # 审批策略：自动允许或拒绝
    return {"decision": "allowed"}

def handle_cancel(params):
    pass

# JSON-RPC stdio 主循环
def main():
    for line in sys.stdin:
        request = json.loads(line)
        method = request["method"]
        params = request.get("params", {})
        
        handlers = {
            "initialize": handle_initialize,
            "prompt": handle_prompt,
            "requestPermission": handle_request_permission,
            "cancel": handle_cancel,
        }
        
        result = handlers[method](params)
        response = {"jsonrpc": "2.0", "id": request["id"], "result": result}
        sys.stdout.write(json.dumps(response) + "\n")
        sys.stdout.flush()

if __name__ == "__main__":
    main()
```

### 3. 使用 `deepseek-harness-sdk` 简化（推荐）

SDK 封装了 JSON-RPC 细端协议，提供高层轮次 API：

```python
# pip install deepseek-harness-sdk
from deepseek_harness import HarnessClient

async def main():
    client = HarnessClient()
    
    # 启动会话
    session = await client.create_session()
    
    # 发送提示词
    result = await session.prompt("请分析这段代码")
    
    # 获取工具调用结果
    for event in result.events:
        print(event)
    
    await client.close()
```

### 4. 在 `cordis.yml` 中注册

将你的 Python Agent 作为 `subagent-acp` 类型的子 Agent 注册：

```yaml
# cordis.yml
- id: subagent-acp
  name: '@deepseek-ai/dsh-subagent-acp'
  config:
    providers:
      my-python-agent:
        # 启动命令：Python 进程的入口
        command: python
        args: ["my_agent.py"]
        # 或使用 uv
        # command: uv
        # args: ["run", "my_agent.py"]
```

### 5. 在 bundle 补丁中挂载

```yaml
# cordis.patch.yml
- insert:
    - id: subagent-acp
      name: '@deepseek-ai/dsh-subagent-acp'
      config:
        providers:
          my-python-agent:

            args: ["-m", "my_package.agent"]
```

## 路径三（进阶）：Python 工具包装为原生 Cordis 插件

如果你只需要暴露**个别 Python 函数**为工具（而非整个 Agent），可以写一个 Cordis 插件，通过子进程调用 Python：

```ts
// my-python-tool.ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'my-python-tool'
export const inject = ['tools', 'subprocess']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'python_analyze',
    description: '调用 Python 分析逻辑',
    parameters: {
      input: { type: 'string', description: '分析输入', required: true },
      format: { type: 'string', enum: ['json', 'text'], description: '输出格式' },
    },
    output: {
      schema: { type: 'string' },
      render(_args, value) {
        return [{ type: 'text', text: value as string }]
      },
    },
    async execute(args, exec) {
      // 通过 subprocess 服务调用 Python
      const result = await ctx.subprocess.run(
        'python', ['-m', 'my_package.cli', '--input', args.input],
        { cwd: exec.cwd },
      )
      return result.stdout
    },
  }))
}
```

对应 `cordis.yml`：

```yaml
- id: my-python-tool
  name: './my-python-tool.ts'
```

# Python SDK 与 ACP 桥接：ACP 协议完整规范与桥接生命周期

---

## 一、架构全貌

ACP Bridge 是一个**双层桥接**架构：

```
Python 进程（生命周期所有者）
    ↕  JSON-RPC over stdio（换行符分隔）
ACP Bridge（@deepseek-ai/dsh-acp，Cordis 插件）
    ↕  内部服务调用
Harness Agent Core（Node 侧拥有 Agent/会话生命周期）
```

- **Python 侧**拥有进程生命周期：启动、stdin/stdout 通信、关闭
- **Node 侧**拥有 Agent 和会话生命周期：通过 `agents` 服务创建 Agent，通过附件接缝准许提示词内容

源码入口：[index.ts](packages/acp/acp/src/index.ts#L43-L128)

---

## 二、ACP 协议四大方法

ACP Bridge 实现 `AcpAgent` 接口，四个方法构成完整协议（[index.ts](packages/acp/acp/src/index.ts#L287-L441)）：

### 1. `initialize` — 握手与能力声明

| 方向 | 作用 |
|------|------|
| Python → Harness | 声明工具列表、模型偏好、协议版本 |

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "0.1",
    "tools": [
      {
        "name": "my_tool",
        "description": "工具描述",
        "parameters": { "type": "object", "properties": { ... } }
      }
    ],
    "modelPreferences": {}
  }
}
```

**关键约束**：
- 必须是连接建立后的**第一个**调用
- 声明的工具列表决定了后续 `prompt` 中 Harness 传入的可用工具
- 返回后，桥接创建 Agent 实例并准备好会话

### 2. `prompt` — 提示词注入与 Agent 执行

| 方向 | 作用 |
|------|------|
| Harness → Python | 传入消息序列，触发 Agent 执行 |

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "prompt",
  "params": {
    "messages": [
      { "role": "user", "content": "请分析这段代码" }
    ],
    "tools": [...],
    "systemPrompt": "...",
    "modelPreferences": {}
  }
}
```

**结算协议（最复杂的生命周期关注点）**：`prompt` 调用在以下三个条件**全部满足**前不会解析：

| 条件 | 含义 |
|------|------|
| **准入完成** | 所有内容块（包括图像附件）已被持久化，且用户消息已进入 Agent 的持久收件箱 |
| **Agent 活动静息** | Agent 已完成由此提示词触发的所有模型调用和工具执行 |
| **助手输出有序交付** | 所有助手输出已按顺序提交，没有进行中的流式片段 |

```
prompt 调用
  │
  ├─ 1. 准入：内容持久化 + 用户消息进入收件箱
  ├─ 2. Agent 执行：模型调用 → 工具执行 → 模型调用 → ...
  ├─ 3. 输出交付：助手消息按序提交
  └─ 4. 结算：prompt Promise 解析
```

### 3. `requestPermission` — 权限审批

| 方向 | 作用 |
|------|------|
| Harness → Python | 请求对工具调用的审批 |

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "requestPermission",
  "params": {
    "toolCall": {
      "name": "shell",
      "arguments": { "command": "rm -rf /tmp/test" }
    },
    "policy": "workspace-write"
  }
}
```

Python 端返回：

```json
{ "decision": "allowed" }
{ "decision": "rejected" }
{ "decision": "cancelled" }
```

**审批策略映射**：

| Harness 策略 | ACP 行为 |
|-------------|---------|
| `always` | 桥接直接返回 `allowed`，不调用 Python |
| `interactive` | 桥接通过 `requestPermission` 转发给 Python |
| `never` | 桥接直接返回 `rejected`，不调用 Python |

### 4. `cancel` — 取消执行

| 方向 | 作用 |
|------|------|
| Harness → Python | 取消进行中的 prompt 执行 |

```json
{
  "jsonrpc": "2.0",
  "id": 4,
  "method": "cancel",
  "params": { "reason": "user_abort" }
}
```

```

  UNINITIALIZED ──────────────→ INITIALIZED

                              prompt()
                                      │
                                      ↓
                                 EXECUTING
                                  ╱    ╲
                requestPermission()    cancel()
                          │               │
                          ↓               ↓
                     APPROVING        CANCELLING
                          │               │
                          ↓               ↓
                       EXECUTING      CANCELLED
                          │
                 Agent 静息 + 输出交付
                          │
                          ↓
                       SETTLED
                          │
                    下一个 prompt()
                          │
                          ↓
                       EXECUTING
```

## 四、内容转换：ACP ↔ Core

这是协议边界的语义映射核心（[content.ts](packages/acp/acp/src/content.ts#L1-L105)）。

### 入站：ACP Prompt → Core Content

`admitAcpPrompt()` 执行**两遍算法**：

| 遍次 | 作用 |
|------|------|
| 第一遍 | 解析 ACP 消息结构，提取文本/图像/工具调用，构建内容块列表 |
| 第二遍 | 通过附件接缝准许每个内容块，持久化图像等二进制数据，组装为 Agent 可消费的格式 |

### 出站：Core Result → ACP Content

桥接将 Harness 的内部事件流转换为 ACP 客户端可消费的通知：

| 内部事件 | ACP 通知 | 内容 |
|---------|---------|------|
| `tool/call` | `on_tool_call` | 工具调用开始 |
| `tool/result` | `on_tool_result` | 工具执行结果 |
| `agent/text` | `on_text` | 模型文本输出 |
| `agent/thinking` | `on_thinking` | 推理内容 |
| `session/event` | `on_notification` | 通用通知 |

## 五、Stop Reason 映射

Harness 内部的停止原因映射到 ACP 标准停止原因（[content.ts](packages/acp/acp/src/content.ts#L215-L238)）：

| Harness Stop Reason | ACP Stop Reason | 含义 |
|---------------------|-----------------|------|
| `end_turn` | `end_turn` | 正常完成 |
| `tool_use` | `tool_use` | 请求工具调用 |
| `max_tokens` | `max_tokens` | 达到输出上限 |
| `stop_sequence` | `stop_sequence` | 命中停止序列 |
| `cancelled` | `cancelled` | 被取消 |

### HarnessClient 核心流程

```python
from deepseek_harness import HarnessClient

async def main():
    client = HarnessClient()
    # 1. 内部启动 runtime-bin（打包的 Node.js 二进制）
    # 2. 建立 stdio JSON-RPC 连接
    # 3. 发送 initialize → 等待响应

    session = await client.create_session()
    # 4. 创建 Agent 会话

    result = await session.prompt("你的任务")
    # 5. 发送 prompt → 等待三条件结算

    for event in result.events:
        print(event)
    # 6. 消费事件流

    await client.close()
    # 7. 关闭：排空子 Agent → 关闭 stdin → 等待 Node 进程退出
```

## 七、桥接拆除与子 Agent 排空

关闭 ACP 连接时（stdin EOF、显式 dispose、进程信号），桥接执行有序拆除（[index.ts](packages/acp/acp/src/index.ts#L443-L524)）：

```
1. 关闭 stdin（通知 Node 侧输入结束）
2. 排空所有进行中的子 Agent
   ├─ 向每个子 Agent 发送 cancel
   ├─ 等待子 Agent 结算或超时
   └─ 丢弃未交付的结果
3. 等待 Agent 的活跃轮次完成
4. 关闭 stdout
5. Node 进程退出
```

**关键保证**：
- 不会遗漏进行中的工具执行——cancel 会传播到整个子 Agent 树
- 图像附件的完整性在交付时（而非提交时）验证——提交后损坏的附件在下一次 prompt 输出时作为 `internal` ACP 错误出现

## 八、通知流与实时传输

`on_notification` 回调在 Agent 运行期间对每条通知触发，实现实时流式传输：

| 通知类型 | 何时触发 | 携带数据 |
|---------|---------|---------|
| `tool_call_start` | 工具调用进入调度管道 | 工具名、参数 |
| `tool_call_result` | 工具执行完成 | 结果内容、isError |
| `text_delta` | 模型输出文本增量 | delta 文本 |
| `thinking_delta` | 推理输出增量 | delta 推理 |
| `status` | Agent 状态转换 | 新状态 |

## 九、权限请求的两级审批

桥接将 Harness 审批瀑布的工具调用批准请求转化为 ACP `requestPermission` 调用，提供两个一次性选项：

| 选项 | ACP 返回 | 效果 |
|------|---------|------|
| 允许本次 | `{ decision: "allowed" }` | 仅本次调用以更宽松策略执行，后续调用恢复原策略 |
| 拒绝 | `{ decision: "rejected" }` | 工具不执行，`isError` 结果进入模型上下文 |

**提权是严格一次性的**——不存在"允许后永久升级"的路径，防止权限蠕变。
